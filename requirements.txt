# Python dependencies for NLP Learning Workflow
#
# EVERY version here is an exact `==` pin, and that is deliberate. This file
# used to be `>=` throughout, which meant a rebuild silently moved the whole
# stack. That already broke this project three separate times: Starlette 1.x
# dropped the legacy `TemplateResponse(name, context)` signature and 500'd
# every HTML page, `pdf_loader` called semchunk with an argument list no
# released semchunk ever accepted and silently fell back to naive chunking
# (fixed since — see below), and atomic-agents started requiring
# Python >= 3.12 which broke the documented `uv venv --python 3.11` recipe.
#
# These are the versions the code is KNOWN GOOD against, captured from a real
# resolved environment, not the newest available. Do not bump anything here to
# fix an unrelated problem.
#
# Two files, one policy:
#   - requirements.txt      (this file) direct dependencies only. Readable, and
#                           the place a human edits to change a version.
#   - requirements.lock.txt full transitive set, `pip freeze` of a known-good
#                           build. This is what the image installs, because the
#                           breakages above came from TRANSITIVE packages
#                           (starlette is not listed below; it arrives via
#                           fastapi) and direct-only pins would not have caught
#                           them.
#
# To upgrade something:
#   1. edit the pin below
#   2. rebuild without the lock:
#        docker build --no-cache --build-arg REQS=requirements.txt -t nlp-reqs-probe .
#   3. capture the new resolution:
#        docker run --rm nlp-reqs-probe pip freeze > requirements.lock.txt
#   4. rebuild normally, exercise the app, commit both files together.
#
